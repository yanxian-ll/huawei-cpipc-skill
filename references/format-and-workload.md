# 格式纪律与模型工作量：双门槛原则

本文件把公开培训材料中一个非常重要的评审经验固化为可执行规则：

> **先用格式纪律保证论文“能被顺畅、认真地评阅”，再用有必要的模型层次与验证链展示真实工作量。**

这是一套写作与建模策略，不是官方评分公式。凡涉及匿名、模板、字体、摘要、引用、AI 使用和提交方式等硬性要求，必须以当年官方文件和赛题要求为最高优先级。

---

# 1. 双门槛

## Gate A：Format discipline —— 先保证不因规范和一致性失分

评委首先接触的是论文成品。即使模型有亮点，匿名泄露、图文不一致、编号混乱、摘要缺结果、结论过度拔高等问题都会显著增加评阅成本，并削弱可信度。

因此，在任何“冲奖优化”之前，先完成格式与一致性门槛。

### A1. 匿名与文件清洁

- 严格遵守当年官方匿名要求。
- 正文、页眉页脚、图片、表格、附录、代码截图中不得残留学校、姓名、导师、队伍编号等禁止出现的身份信息。
- 最终导出文件应检查文档属性、PDF 元数据、批注、隐藏文本等是否留下不必要的身份信息；这属于稳妥的提交卫生检查，不应被表述成官方新增条款，除非当年规则明确要求。

### A2. 摘要必须能独立说明论文核心

摘要至少应让评委独立读出：

`任务 -> 方法/模型 -> 关键结果 -> 结论 -> 创新/特点`

2026 官方摘要要求见 `official-2026.md`。若培训材料要求“摘要独立成页”，执行时仍以当年官方模板版式为准，不得自行破坏模板。

### A3. 图、表、公式、符号和单位形成统一系统

- 图、表、公式编号连续且引用对应。
- 重要符号有定义，全文同一符号保持同一含义。
- 单位统一；量纲敏感的公式必须检查量纲。
- 图题、表题、坐标轴、图例、单位齐全。
- 论文中的模型名、指标名、变量名不要在不同章节随意换称呼。

### A4. 正文、图表、附件代码/结果必须互相核对

至少建立一张内部一致性表：

| 对象 | 正文 | 图/表 | 代码/附件 | 一致？ |
|---|---|---|---|---|
| 模型名称 | | | | |
| 参数值 | | | | |
| 核心结果 | | | | |
| 单位 | | | | |
| 样本规模 | | | | |
| 最优方案/排序 | | | | |

禁止出现：

- 正文写 0.873，表格写 0.837；
- 图中使用 10% 扰动，正文称 20%；
- 论文声称使用模型 A，附件实际运行模型 B；
- 正文说保留 1200 个样本，代码结果是 1184 个；
- 结论中的排序与结果表不一致。

### A5. 结论只写被模型和证据支撑的结果

结论可以总结、归纳、说明适用范围，但不能把“当前数据下的模型结果”拔高成没有证据支持的普适规律。

高风险：

> 该模型证明了此策略在所有场景下均为最优。

如果实际只在给定数据和若干扰动场景下验证，应写成：

> 在本文数据与所测试的参数范围内，该策略保持较低目标值，核心方案未发生改变。

# 2. Gate B：Model workload —— 用有理由的层次体现工作量

“模型复杂度”不等于模型越多越好，更不等于堆叠热门算法。真正可见的工作量来自：

> **题目难点被逐层识别，每增加一层模型或实验，都解决一个上一层解决不了的问题，并留下可验证的证据。**

推荐使用以下五层结构检查模型工作量。

## Level 0：基础可运行层

目标：先把问题真正跑通。

至少做到：

- 输入、输出明确；
- 基础模型可求解；
- 结果可复现；
- 关键参数可追溯；
- 输出直接回答赛题至少一个要求。

如果基础层都无法复现，不要急着增加高级算法。

## Level 1：机制融合层

问题：模型是否真正理解了赛题里的产业、物理、工程、经济或业务机制？

优先把题目机制嵌入：

- 目标函数；
- 约束；
- 状态转移；
- 守恒关系；
- 几何/物理关系；
- 业务规则；
- 时空结构；
- 因果顺序或系统边界。

这通常比简单换一个更复杂的机器学习模型更有建模价值。

检查句：

> 如果把赛题背景名词全部替换掉，这个模型是否仍然一字不改？

如果答案是“是”，需要警惕模型可能只是通用数据拟合，没有充分利用题目机制。

## Level 2：优化增强层

只有当基础方法确实处理不了核心困难时，再引入增强算法，例如：

- 非凸优化；
- 组合优化；
- 大规模搜索；
- 多目标权衡；
- 离散决策；
- 复杂约束；
- 难以获得解析解的问题。

可以使用启发式/元启发式算法，但必须回答：

1. 基础方法为什么不够？
2. 新算法解决了哪个计算困难？
3. 新算法是否真的改善了目标值、可行率、速度或稳定性？
4. 如果是启发式算法，是否避免无依据声称“证明全局最优”？

不要为了“看起来工作量大”同时堆 GA、PSO、SA、ACO，却没有比较和选择理由。

## Level 3：不确定性层

当结论会受到随机性、测量误差、参数估计误差、场景变化影响时，考虑：

- Monte Carlo；
- 鲁棒优化；
- 贝叶斯方法；
- 随机规划；
- 区间分析；
- 情景分析；
- bootstrap / 重采样；
- 参数扰动实验。

关键不是出现这些名词，而是明确：

`不确定性来自哪里 -> 如何建模 -> 如何传播到结果 -> 是否改变最终决策`

如果题目几乎没有关键不确定性，不要机械增加“蒙特卡洛”章节。

## Level 4：验证反馈层

形成闭环：

`建模 -> 求解 -> 验证 -> 发现问题 -> 调整模型/参数 -> 再验证`

常见工具：

- 灵敏度分析；
- 误差分析；
- 交叉验证；
- 留出测试；
- 与基准方法比较；
- 极端场景/边界测试；
- 消融实验；
- 约束可行性检查；
- 稳健性测试。

验证不是单独为了“多一节”，而是回应评委最核心的问题：

> **为什么应该相信这个答案？**

---

# 3. 复杂度必须是“有必要的复杂度”

任何新增模型层，在进入论文前都必须填写：

| 层次 | 对应赛题难点 | 新增机制/方法 | 新增证据 | 相比上一层的增量价值 | 是否保留 |
|---|---|---|---|---|---|
| 基础层 | | | | | |
| 机制层 | | | | | |
| 优化层 | | | | | |
| 不确定性层 | | | | | |
| 验证层 | | | | | |

只有当“对应难点”和“增量价值”能说清，才建议保留这一层。

## 删除无效复杂度

出现以下情况应优先删减：

- 增加一个模型但最终答案完全不依赖它；
- 高级算法没有比简单基线更好；
- 复杂模型没有新的可解释机制，只增加参数量；
- 做了大量图，但没有改变任何判断；
- 敏感性分析扰动了与结论无关的参数；
- 叠加多个算法却没有消融、基线或选择依据；
- 使用深度学习只是因为“高级”，但数据规模和任务并不需要。

复杂度的目标不是“让论文显得难”，而是让评委看到团队针对不同困难完成了不同层次的工作。

---

# 4. Architecture mode 必须执行双门槛检查

设计论文与模型路线时，除 question-to-evidence matrix 外，再建立：

## 4.1 Format gate

- 匿名/模板风险；
- 摘要是否能覆盖方法、结果、创新；
- 图表/公式/符号/单位规范计划；
- 正文—图表—附件一致性计划；
- 结论证据边界。

## 4.2 Workload ladder

逐问判断是否需要：

`基础可运行 -> 机制融合 -> 优化增强 -> 不确定性 -> 验证反馈`

不是每一问都必须五层齐全。应根据赛题难点裁剪。

---

# 5. Audit mode 必须同时回答两个问题

## Format audit

> 这篇论文有没有因为格式、匿名、图文一致性、单位、编号、摘要或结论越界而被低估的风险？

## Workload audit

> 评委能否从论文中清楚看到团队到底做了哪些层次的工作？每一层是否都有必要、有结果、有验证？

如果存在“做了很多但论文看不出来”，应优先改善结构、图表和证据表达；如果存在“论文看起来复杂但实际没有增量价值”，应删掉无效复杂度。

---

# 6. 最终原则

可以把这套策略压缩成两句话：

> **格式规范降低评阅摩擦，先让论文可信、可读、可核对。**
>
> **模型层次展示真实投入，但复杂度必须由赛题难点驱动，并由增量证据证明。**

二者缺一不可，但永远不要为了“展示工作量”牺牲正确性、可解释性、可复现性和证据链。
