# 章节边界：同一信息在摘要、引言、问题分析、正文与结论中怎么分工

本文件解决一个高频问题：**同一项工作应该在哪个章节写到什么程度？**

核心原则：同一事实可以在多个章节出现，但每次出现承担的功能必须不同。不要把同一段话换几个近义词后分别放进摘要、引言和结论。

---

# 1. 一条信息只能有一个“主家”

对每项信息先指定主章节，再决定其他章节是否需要压缩引用。

| 信息类型 | 主章节 | 其他章节允许出现的方式 |
|---|---|---|
| 题目最终要求 | 问题重述 | 摘要/结论中压缩成任务或答案 |
| 为什么这样拆题 | 问题分析 | 摘要中只保留一句总体思路 |
| 模型数学定义 | 模型建立 | 摘要只报模型名称和关键结构 |
| 算法步骤与参数 | 模型求解 | 摘要只报关键算法；结论通常不写 |
| 具体数值结果 | 结果与分析 | 摘要和结论可以重复关键数字 |
| 数值意味着什么 | 结果与分析 | 结论可以压缩为最终发现 |
| 验证与稳健性 | 检验/敏感性 | 摘要、结论各压缩一句 |
| 现实背景 | 引言/问题背景 | 摘要最多 1–2 句，结论通常不写 |
| 模型局限 | 模型评价/结论 | 摘要通常不展开 |
| 创新点 | 模型/方法对应位置 | 摘要压缩总结；不能只在摘要里宣称 |

若某项“创新”只在摘要里出现、正文找不到具体实现，视为高风险。

---

# 2. 摘要 vs Introduction / 问题背景

## 摘要回答

> **我们做了什么，怎么做，得到了什么，可靠性和创新在哪里？**

允许重点：`T M R E V C`

摘要中的方法与结果必须足够具体，使评委不读正文也能理解论文主线。

### 摘要中的典型句子

- “针对……，建立……模型。”
- “采用……估计……，并利用……求解。”
- “得到……为 XXX，较……变化 XX%。”
- “在……扰动下，核心结论保持稳定。”

## Introduction / 问题背景回答

> **为什么要研究这个问题？困难在哪里？本文准备怎样解决？**

允许重点：`B T D C`

### Intro 中的典型句子

- “……系统需要在……约束下实现……。”
- “然而，……导致……难以同时满足……。”
- “现有……方法适合处理……，但本题还存在……约束。”
- “为此，本文从……、……两个层面展开建模。”

## 快速判别

若一句话含**最终数值**，通常更像摘要/结果/结论，不像 Intro。

若一句话主要解释**问题为何重要、为什么难**，通常属于 Intro，不属于摘要主体。

### 错误迁移示例

错误 Intro：

> 本文采用 XGBoost、遗传算法和蒙特卡洛方法，问题一精度达到 97.31%，问题二成本降低 18.4%，问题三得到……

这已经在复述摘要。

改为 Intro：

> 本题同时包含状态识别与受约束决策两个层次，前者需要从高维观测中提取稳定特征，后者还需考虑资源容量与时间约束。为避免将两个任务割裂处理，本文先构造状态表征，再将其作为后续优化模型的输入。

# 3. 问题重述 vs 问题分析

## 问题重述回答

> **题目给了什么？要求输出什么？**

主要角色：`B T`

不要出现：

- 模型选择；
- 算法名称；
- 求解过程；
- 最终结果；
- 团队自行增加的假设。

示例：

> 问题二要求在给定设备容量和任务到达信息的条件下，确定各任务的分配与执行顺序，使总完成时间尽可能小，并给出最终调度方案。

## 问题分析回答

> **我们把它看成什么问题？关键变量是什么？为什么用这条路线？**

主要角色：`T D M V`

示例：

> 问题二的核心是同时决定任务分配与执行顺序，两个决策通过设备占用时间相互耦合，因此可将其表示为带资源约束的组合优化问题。以任务指派和开始时间为决策变量，构造最大完工时间目标，并使用整数规划描述容量与先后关系；随后采用……求解，并通过下界或基准方案验证解的质量。

## 一句话判别

- “要求我们做什么？” -> 问题重述。
- “我们为什么准备这样做？” -> 问题分析。

# 4. 问题分析 vs 模型建立

## 问题分析

保留**概念层级**：

> 因为 A 影响 B，所以将 A 设为状态量，用某类关系刻画 B，并以 C 为优化目标。

## 模型建立

进入**数学层级**：

- 集合与索引；
- 决策变量；
- 参数；
- 目标函数；
- 约束；
- 概率分布/状态方程/损失函数；
- 公式推导与现实含义。

示例：

问题分析写：

> 为同时考虑成本和等待时间，将二者构成加权目标，并用容量约束保证方案可执行。

模型建立写：

> 记 $x_{ij}\in\{0,1\}$ 表示任务 $i$ 是否分配至设备 $j$，定义总成本……，目标函数为……；式（5）限制每个任务仅分配一次，式（6）保证任一时刻设备负载不超过容量上限。

如果问题分析已经出现一页公式，通常写得太深。

---

# 5. 模型建立 vs 模型求解

## 模型建立回答

> **我们定义了哪个数学问题？**

应该出现：

- 数学对象；
- 目标；
- 约束；
- 参数来源；
- 机制关系。

## 模型求解回答

> **这个数学问题具体怎样算出解？**

应该出现：

- 解析解/数值法/优化器/算法选择理由；
- 初始化；
- 迭代流程；
- 关键超参数；
- 收敛/停止条件；
- 随机算法重复实验设置；
- 软件仅作为实现环境，而不是方法本身。

### 错误

> 利用 Python 对上述模型进行求解，得到结果如下。

“Python”不能替代求解方法。

### 更完整

> 该模型含有整数决策变量和非线性容量约束，难以直接获得解析解。本文采用……算法，以……作为初始解；每轮迭代依次执行……，当连续 XXX 轮目标值改善小于 XXX 时停止。算法在 Python XXX 环境中实现。

# 6. 结果 vs 分析 vs 验证

三者经常混在一起，应明确拆分。

## 结果 `R/E`

回答：**算出了什么？**

> 最优方案的目标值为 XXX，其中总成本为 XXX、平均等待时间为 XXX。

## 分析 `I`

回答：**这些数字说明什么？**

> 与基准方案相比，成本下降主要集中在高需求时段；同时等待时间未明显上升，说明成本改善并非由牺牲服务水平获得。

注意：若“主要集中”“由……导致”没有证据，应改成保守表述。

## 验证 `V`

回答：**为什么相信它？**

> 对参数 $\lambda$ 施加 ±10% 扰动后，目标值变化不超过 XXX%，且最优方案中的 XXX 项决策保持不变。

不要把“结果看起来合理”当作模型检验。

# 7. 摘要 vs 结论：最重要的边界

二者都可以出现关键数字，但承担不同任务。

## 摘要

结构更接近：

`问题 -> 方法 -> 模型 -> 关键结果 -> 验证 -> 创新`

方法信息较多。

## 结论

结构更接近：

`问题 -> 最终答案 -> 关键证据 -> 稳健性 -> 总体发现 -> 适用边界`

答案信息较多，方法信息较少。

### 同一工作在两处应该如何变形

假设正文使用改进遗传算法求车辆路径。

摘要：

> 对问题二，建立考虑时间窗和容量约束的车辆路径模型，并采用引入自适应变异率的遗传算法求解。最终总里程为 XXX km，较基准方案下降 XX%。

结论：

> 问题二得到的最终车辆路径方案总里程为 XXX km，满足全部时间窗和容量约束，较基准方案减少 XX%；在需求量 ±10% 扰动下，主干路线保持不变。

结论不需要再次解释交叉率、变异率和种群规模。

# 8. 模型评价 vs 结论

## 模型评价

回答：

- 模型为什么有效；
- 哪些结构是优点；
- 哪些假设造成局限；
- 怎样改进；
- 推广到其他场景需要什么条件。

## 结论

回答：

- 每问最终答案；
- 最重要发现；
- 可靠性；
- 必要的边界。

结论不是“优缺点列表”。若篇幅紧张，可在结论末尾用 1–2 句提最关键局限。

# 9. 重复度诊断算法

审稿时对每一段执行：

1. 写出该段的主职责标签，如 `B/D`、`M`、`R/E`。
2. 搜索全文是否存在承担同一职责且表达同一内容的段落。
3. 若两个章节既内容相同、职责也相同，删除或合并一处。
4. 若内容相同但职责不同，重写到不同粒度。

例如，同一个“准确率 96.8%”可以：

- 摘要：用于压缩展示主要结果；
- 结果章节：给完整表格、基准比较、误差分布；
- 结论：作为最终可靠性证据。

这不属于无意义重复，因为三处粒度不同。

# 10. 章节边界自检问题

完成一节后只问一个问题：

- 摘要：如果评委只读这里，知道**方法和结果**了吗？
- Intro：读完知道**为什么研究、难在哪里**了吗？
- 问题重述：知道**题目究竟要交付什么**了吗？
- 问题分析：知道**为什么选择这条建模路线**了吗？
- 模型建立：知道**数学问题具体是什么**了吗？
- 模型求解：知道**如何复现求解过程**了吗？
- 结果与分析：知道**得到什么、意味着什么**了吗？
- 验证：知道**为什么相信结论**了吗？
- 结论：知道**每一问最终答案是什么**了吗？

若回答成了另一个章节的问题，说明内容越界。
