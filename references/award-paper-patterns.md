# 优秀/获奖论文的可迁移写作模式

本文件总结公开获奖作品、获奖队伍经验与数学建模写作教学中**可迁移的表达模式**。这些是经验规律，不是华为杯官方评分条款。

任何年份的具体获奖论文都可能包含个人风格、题型特性和当年模板要求，因此只能学习其组织逻辑，不能机械仿写句子，更不能复制文本。

---

# 1. 证据层级

使用以下优先级理解“优秀论文模式”：

1. **当前年度官方规则**：决定必须做什么；
2. **官方优秀论文归档/官方获奖信息**：说明哪些作品曾被官方认可；
3. **作者公开的获奖论文与代码仓库**：可观察真实工作流，但奖项描述主要来自作者自述时应注明；
4. **高校获奖经验交流**：用于理解常见评阅与表达经验；
5. **公开写作教学**：用于形成通用写作模板。

不要把第 3–5 层写成“官方规定”。

# 2. 可迁移模式一：摘要按“问题”推进，而不是按“模型名”堆砌

高质量竞赛摘要更接近：

`总任务 -> 问题1的方法+结果 -> 问题2的方法+结果 -> ... -> 验证/创新`

而不是：

`用了A模型、B算法、C软件、D指标`

## 推荐结构

### 开头 1–2 句

只做两件事：

- 定义整篇论文处理的核心对象；
- 交代统一技术路线（如果确实存在）。

### 每问一个微闭环

每个子问题至少完成：

`任务 T -> 方法 M -> 结果 R/E`

若该问的可靠性很关键，再补 `V`。

例如：

> 对问题二，为处理……约束，建立……模型，并采用……求解。最终得到……为 XXX，其中……；相较基准方案……。

这种写法让评委能把摘要与赛题逐问对应。

---

# 3. 可迁移模式二：正文围绕子问题组织，评委能快速导航

对多问型赛题，优先采用：

```text
问题一
  问题一分析
  模型建立
  模型求解
  结果与分析
  小结/答题句

问题二
  ...
```

而不是把全文拆成：

```text
所有模型
所有算法
所有结果
```

后一种结构容易迫使评委跨很多页寻找“哪一个结果回答哪一问”。

如果多个问题共享一个基础模型，可以先建立公共模型，再在各问题章节明确说明“本问在基础模型上新增/修改了什么”。

---

# 4. 可迁移模式三：问题分析是“路线图”

公开教学与竞赛经验反复强调问题分析的承上启下作用。高质量写法不是：

> 问题一使用 XXX 模型。问题二使用 YYY 模型。

而是解释：

1. 这问本质是什么；
2. 为什么直接方法不够；
3. 哪些变量/关系最关键；
4. 因此如何转化成数学问题；
5. 最后怎样验证。

推荐句序：

`任务本质 -> 难点 -> 建模决策 -> 求解路线 -> 验证计划`

如果使用流程图/思维导图，图中节点也应对应这条逻辑，而不是只把章节标题画成框。

---

# 5. 可迁移模式四：公式必须“翻译”回题目

竞赛论文不是纯数学推导。一个关键公式至少要让评委知道：

- 为什么出现；
- 每个核心量是什么意思；
- 哪一项对应题目中的哪种机制；
- 参数从哪里来；
- 约束对应什么现实限制。

因此模型章节应形成：

`建模目的 -> 变量 -> 公式 -> 现实含义 -> 参数来源 -> 约束解释`

如果连续半页都是公式而没有解释，评委很难确认模型与题意的连接。

---

# 6. 可迁移模式五：结果段先给“发现”，再给图表

图表不是结果分析本身。

高信息密度的段落通常具备：

`关键发现 -> 数字证据 -> 比较 -> 解释 -> 对题目的回答`

例如：

> 方案 C 的目标值最低，为 XXX（表 5），较基准方案 A 降低 XX%。同时约束指标 Y 保持在 XXX 以下，因此该改进不是以违反服务约束为代价。问题二最终选用方案 C。

不要写：

> 结果见表 5。由表可知方案 C 最好。

---

# 7. 可迁移模式六：优秀表达通常“数值先于形容词”

优先：

> 测试集 MAE 为 XXX，较基准下降 XX%。

而不是：

> 预测效果很好，精度有明显提升。

优先：

> 参数 ±10% 扰动下，目标值变化不超过 XXX%。

而不是：

> 模型稳定性较强。

竞赛评审需要在很短时间判断工作量和可信度，数字比自我评价更有效。

---

# 8. 可迁移模式七：验证必须匹配题型

不要为了“论文完整”机械加一个敏感性分析。

不同题型更自然的验证包括：

- 预测：测试集、交叉验证、时间滚动验证；
- 定位/估计：与真值比较、误差分布；
- 优化：可行性检查、基准方案、上下界、重复运行；
- 分类：混淆矩阵、F1、类别误差；
- 机理模型：特殊情形、边界条件、守恒关系；
- 评价排序：权重扰动、方法替换、排序一致性。

验证段的目标是回答：**为什么评委应该相信最终答案？**

---

# 9. 可迁移模式八：结论按题目逐问回答

竞赛结论首先是“答案索引”，其次才是学术式总结。

推荐：

1. 一句总体完成内容；
2. 问题一最终答案 + 核心数字；
3. 问题二最终答案 + 核心数字；
4. ……；
5. 一句验证/稳健性；
6. 一句最重要的总体发现或适用边界。

不推荐在结论重新讲：

- 算法完整步骤；
- 网络层数；
- 遗传算法参数；
- 完整公式；
- 大段现实背景。

---

# 10. 可迁移模式九：把代码输出变成论文证据，而不是把代码过程写成正文

公开的一等奖代码仓库表明，实际参赛工作可能包含大量预处理、训练、定位、可视化和预测脚本。论文正文不需要复述代码文件，而应抽象为可验证的方法链：

`原始数据 -> 预处理规则 -> 特征/参数 -> 模型 -> 求解 -> 输出指标 -> 验证`

例如代码做了聚类、去噪和神经网络分类，正文应回答：

- 为什么需要聚类/去噪；
- 聚类数怎么确定；
- 网络输入输出是什么；
- 训练/验证如何划分；
- 最终误差是多少；
- 去噪前后差多少。

“调用 sklearn / PyTorch / MATLAB”不是论文贡献。

---

# 11. 可迁移模式十：创新点必须能在正文定位

创新点写法使用：

`已有/直接做法 -> 本题困难 -> 本文改动 -> 带来的可验证收益`

例如：

> 直接使用固定权重无法适应不同时段的需求差异，因此本文根据……构造时变权重，并将其嵌入目标函数。与固定权重基准相比，……指标下降 XX%。

不要写：

> 本文模型具有较强创新性。

如果无法指出“改了什么”，就不要强行称为创新。

---

# 12. 一等奖样本不是万能模板

从获奖样本学习时，Codex 必须避免：

- 复制样本原句；
- 因为获奖论文用了神经网络就强迫新赛题也用神经网络；
- 模仿复杂模型名称以制造高级感；
- 把旧年份格式当成 2026 格式；
- 把某个作者的排版习惯说成官方要求。

真正可迁移的是：

**问题与模型对应清楚、方法有理由、结果有数字、图表有解释、结论直接答题、全文可复现。**

---

# 13. Skill 使用方式

当用户要求“按一等奖论文风格写”时，不模仿具体作者措辞。执行：

1. 读取本文件得到结构特征；
2. 读取 `section-boundaries.md` 防止章节复读；
3. 读取 `evidence-writing.md` 强化数值证据；
4. 只使用用户真实模型与真实计算结果；
5. 输出适合当前赛题的原创组织与表述。

若用户提供一篇获奖论文作为参考，可以学习其结构，但任何复用都要避免近似复制其表述或独特文本。
